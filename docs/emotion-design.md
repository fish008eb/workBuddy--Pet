# 情绪系统设计 · Emotion Design

> 目标：让面板从「用量仪表盘」变成「会表达的搭子」。宠物不再每轮只报数字，而是根据用量、时间、节奏自己表达情绪。
>
> 本文是产品向设计文档；实现细节见 `src/pet-emotion.js`、`src/pet-event-writer.js`、`src/pet-ledger.js` 与 `src/WbPet.cs`。

---

## 一、设计原则

1. **自动，不打扰**：不需要用户点击、不需要配置，宠物自己判断该说什么。
2. **有节流**：宁可少说，不要刷屏。10 分钟内最多 3 句，同一情绪 3 分钟内不重复。
3. **说人话**：不堆数字，一句话 + 一个具体动作建议。
4. **不制造压力**：只为「担忧/心疼」这两级负面情绪，不做愤怒、不做惩罚、不做打卡压力。
5. **可换人格**：同一件事，三种说法，用户自己选。

## 二、情绪模型

| id | 名称 | 什么时候出现 | 强调色 | 动作 |
|---|---|---|---|---|
| `happy` | 开心 | 缓存良好、跨天首轮、打盹醒来 | `#F9A8D4` | 弹跳 |
| `proud` | 得意 | 缓存破纪录、积分里程碑、轮次里程碑 | `#FBBF24` | 三连弹跳 |
| `worried` | 担忧 | 单轮烧太多、缓存崩、数据算不出来 | `#F87171` | 横向抖动 |
| `tender` | 心疼 | 连续工作 2h/4h、久坐 90 分钟 | `#FDA4AF` | 缓慢呼吸 |
| `sleepy` | 困倦 | 23:00–06:00、无活动 15 分钟 | `#6B7B9E` | 降帧 + 半透明 |
| `surprised` | 惊讶 | 单轮 token 或调用数异常 | `#A78BFA` | 挤压回弹 |
| `calm` | 平静 | 默认，不说话 | `#333949` | 无 |

**表达通道**（不需要新美术素材）：

| 通道 | 表现 |
|---|---|
| 文案 | 气泡里单独一行，带 emoji，一句话 |
| 强调色 | 气泡描边 + 尾巴同步变色，不换底色（避免闪烁） |
| 标题 | `😺 可爱治愈` + 时间 |
| 动作 | 弹跳 / 抖动 / 挤压 / 呼吸 / 降帧 |
| 常驻状态 | 睡着时角色半透明 + 动画帧率降到 1/2.2 |

## 三、触发规则

### 3.1 单轮规则（每轮回答结束，由 Stop hook 判定）

| # | 条件 | 情绪 |
|---|---|---|
| 1 | 单轮输入 ≥ 2000 万，或 ≥ 近期均值的 3 倍 | surprised |
| 2 | 单轮调用次数 ≥ 40 | surprised |
| 3 | 单轮积分 ≥ 5 且 ≥ 近期均值的 3 倍 | worried |
| 4 | 缓存命中 ≥ 99.5% 且破历史最好（≥5 次调用） | proud |
| 5 | 缓存命中 ≥ 99.0% | happy |
| 6 | 缓存命中 < 85%，或比近期均值跌 10 个百分点 | worried |
| 7 | 今日积分首次跨过 50 / 100 / 200 / 500 | proud |
| 8 | 首次使用（无历史记录） | happy |
| 9 | 累计轮次跨过 10 / 50 / 100 / 500 | proud |
| 10 | 今日汇总失败（读不到日志） | worried |
| 11 | 会话日志文件不存在 | worried |

相对判定（「3 倍均值」）用指数滑动平均（α=0.3）计算；冷启动前 5 轮只看绝对值，避免误报。

### 3.2 时间规则（面板自己的时钟，每 30 秒检查）

| # | 条件 | 情绪 |
|---|---|---|
| 12 | 连续工作超过 2 小时 / 4 小时 | tender |
| 13 | 本地时间 23:00–06:00 且有活动 | sleepy |
| 14 | 无活动 ≥ 15 分钟 | sleepy（打盹） |
| 15 | 打盹中出现新事件 | happy（醒来） |
| 16 | 连续 90 分钟没有 10 分钟以上的中断 | tender（久坐） |
| 17 | 跨天后的第一轮 | happy |

### 3.3 预留（本期未实现）

`UserPromptSubmit`（开工）、`Notification`（等授权）、`PostToolUseFailure`（被中断）需要额外 hook，默认关闭。**不使用** `PreToolUse` / `PostToolUse`：每次工具调用都要起进程，一轮几十次会造成可感知的延迟。

## 四、节流规则

| 规则 | 值 | 为什么 |
|---|---|---|
| 每轮最多 | 1 条气泡 | 一轮弹 5 次就没法看了 |
| 非紧急间隔 | ≥ 45 秒 | 有节奏感 |
| 10 分钟内上限 | 3 条 | 防刷屏 |
| 同情绪冷却 | 3 分钟 | 连续烧 token 时不反复念叨 |
| 紧急例外 | 数据降级类每轮 1 条，不受 45 秒限制 | 出问题必须立刻说 |
| 鼠标悬停时 | 挂起不打断，移开立即补播；60 秒未移开则丢弃 | 用户正在看数字 |
| 陈旧事件 | 超过 120 秒的直接丢弃 | 关一夜再打开不会连播 80 条 |

**情绪不排队**：同批次只播最高优先级一条，其余直接丢弃——延后的情绪是过期情绪。

## 五、人格与唠叨程度

### 5.1 三套人格

| id | 名称 | 风格 | 例句 |
|---|---|---|---|
| `cute` | 可爱治愈 | 软萌、带语气词 | `缓存 99.8%，新纪录！我记小本本上了 😻` |
| `snark` | 毒舌吐槽 | 嫌弃但关心 | `269万 token，你是把整个仓库喂进去了？🙄` |
| `eng` | 克制工程师 | 短句、报事实 | `缓存 99.8%，刷新历史最好。🏆` |

### 5.2 三档唠叨

| 档位 | 说什么 |
|---|---|
| **克制（默认）** | 只在异常、里程碑、深夜、久坐时开口；普通轮次安静 |
| 话痨 | 每轮都说一句，带本轮数据 |
| 极简 | 只在数据降级和里程碑开口 |

人格与档位都在右键菜单里切换，写入 `pet-state.txt`，重启后保留。

## 六、文案约定（`assets/personas.txt`）

```
persona|cute|可爱治愈|#F9A8D4
line|cute|cacheBest|1|缓存 {cache}%，新纪录！我记小本本上了|😻
```

- `persona` 行定义人格：id、显示名、强调色
- `line` 行定义文案：人格、触发 key、变体号、文案、emoji
- 同一 key 可以有多个变体（1、2…），按轮次随机选，避免重复感
- 允许的占位符：`{in} {out} {cache} {credit} {calls} {today} {n} {h} {name}`
- 取模板三级兜底：指定变体 → 变体 1 → 代码内置兜底句

**改词不用改代码**：编辑 `assets/personas.txt`，重启面板（或右键 Refresh 后重启）即可。

## 七、数据流

```
Stop hook (turn-usage.js)
   ├─ 读 pet-ledger.txt（历史统计：EMA、最好缓存、累计轮次、今日积分）
   ├─ evaluateTurn() 判定规则 1–11 → 情绪事件
   ├─ 追加到 pet-events.txt（seq|ts|turnId|emotion|pri|motion|accent|title|text|dur）
   └─ 更新 pet-ledger.txt

面板 (WbPet.exe)
   ├─ 每 600ms 读 pet-events.txt（按偏移量增量读，seq/turnId 去重）
   ├─ 节流判定 → 渲染气泡 + 播放动作
   ├─ 每 30s 自检时间规则 12–17
   └─ 写 pet-state.txt（位置、人格、档位、已读偏移）
```

三个文件三个写者，互不加锁：`pet-events` 只由 hook 写、`pet-ledger` 只由 hook 写、`pet-state` 只由面板写。

## 八、已知取舍

| 取舍 | 原因 |
|---|---|
| 不用 JSON | C# 版没有 JSON 库，加字段会静默失效；`key=value` 与 `\|` 定长列两端都只靠 `Split` |
| 情绪只在 C# 版完整生效 | PowerShell 版保留用量与换肤，不读情绪文件，避免双份实现与重复弹窗 |
| 不做点击互动 | 鼠标左键已被拖拽占用；点击与拖拽的区分需要额外状态机，收益不抵成本 |
| 不做养成数值 | 亲密度/等级会引入「必须每天用」的压力，与「不制造压力」原则冲突 |
| 不做愤怒/悲伤 | 自用工具，负面情绪到「担忧/心疼」为止 |
